How a transformer works

The architecture underneath every current language model. This is the conceptual scaffold — read it, then go play with a live one.

A transformer is a function. It takes a sequence of tokens and returns a probability distribution over what token comes next. Everything else — chat, code generation, tool use, the appearance of reasoning — is that one function called repeatedly.

What makes it work is a single idea: every token gets to look at every earlier token and pull in whatever it needs. Prior architectures passed information along a chain, one step at a time, which meant long-range dependencies had to survive a long relay. Attention lets any position read from any earlier position directly, in one hop, and it does all positions in parallel. That parallelism is why these models could be scaled to the size they are.

Tokens

Text is chopped into tokens — sub-word chunks learned from a corpus by a merge algorithm (byte-pair encoding). Common words are single tokens; rare words fragment. A leading space is usually part of the token, which is why the and the are different entries.

Each token ID indexes into an embedding table, producing a vector — a list of a few thousand numbers. That vector is the token's starting representation. Position information gets folded in too, because attention itself is order-blind: without it, "Jupiter orbits the probe" and "The probe orbits Jupiter" would be identical inputs.

Attention

This is the mechanism. Each token produces three vectors by multiplying its representation by three learned weight matrices:

  • Query — what this token is looking for.
  • Key — what this token offers to others.
  • Value — what this token actually hands over if selected.

The database analogy is close enough to be useful and wrong enough to flag: it is a soft lookup. You don't retrieve one row. You take a weighted blend of every row, where the weights come from how well each key matches your query.

Why the scaling and the mask are there

The ÷√d step keeps dot products from growing with dimension. In a 5,000-dimensional space raw dot products get large, softmax saturates, and gradients vanish. Dividing by the square root of the dimension holds the variance roughly constant.

The causal mask sets every score for a future position to negative infinity, so softmax gives it exactly zero weight. Token 3 can see tokens 1–3 and nothing beyond. This is what makes the model autoregressive, and — as it happens — it is the entire reason prompt caching is possible. Hold that thought; it's the subject of the third document.

Many heads, different jobs

One attention pattern per layer would be limiting. Real layers run dozens of heads in parallel, each with its own Q/K/V matrices, each free to specialise. Their outputs are concatenated and mixed.

The rest of the block

Attention moves information between positions. The other half of each layer — a two-layer feed-forward network, applied to each position independently — does the processing within a position. It's typically 4× wider than the model dimension, and it holds most of the parameters. Current interpretability work suggests much of what we'd loosely call factual knowledge lives here, in patterns of neuron activation, rather than in the attention weights.

Both sublayers write into a shared residual stream: rather than replacing the representation, each block computes an update and adds it. The stream runs unbroken from embedding to output, and every block reads from it and writes back into it.

Stack that block 40–120 times and you have the model. Rough intuition for what the depth buys: early layers resolve tokens into words and local syntax, middle layers build the semantic content, late layers narrow toward a specific prediction. That's a simplification, but a serviceable one.

Turning vectors into a word

At the top of the stack, the vector at the final position is multiplied by an output matrix to give one score — a logit — for every token in the vocabulary. Softmax converts those to probabilities. Then something has to choose.

Two things worth noticing here. First, at temperature 0 the model is deterministic: same input, same output, every time. The variability you see in chat is a sampling choice, not something intrinsic. Second, the model has no notion of a sentence, a plan, or a conclusion. It emits one token, appends it to the input, and runs the entire stack again. Any longer-range structure is an emergent property of doing that repeatedly with a good enough distribution.

The cost consequence. Generating token n requires attending over all n−1 previous tokens. Done naively, producing a 1,000-token response means re-running attention over the whole prompt a thousand times. The fix is to keep every token's Key and Value vectors in GPU memory after computing them once — the KV cache. This is a different thing from the prompt caching on your bill, and confusing the two is the usual source of the confusion. Both are in the third document.

What is not in there

Things people reasonably assume are present and are not:

  • No memory across calls. No hidden state survives a request. Every turn re-sends the whole conversation and reprocesses it from scratch.
  • No variable compute. A hard question and an easy one both get exactly the same number of layers. "Thinking" tokens are the workaround — they buy more forward passes by generating intermediate text to condition on.
  • No lookup table. Nothing is stored verbatim and retrieved. Facts are distributed across billions of weights, which is why they can be subtly wrong in ways a database never is.
  • No separate confidence signal. The probability distribution is the only thing there is. A confidently-worded wrong answer and a confidently-worded right one can be produced by very similar internal states.
